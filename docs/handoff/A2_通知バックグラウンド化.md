# A2: 通知処理のバックグラウンド化 (waitUntil パターン)

**問題**: 承認ボタン → SMTP メール送信 → LINE WORKS API 送信 → やっと画面遷移
という同期処理だと、外部API待ちで **1〜3.5秒** 固まる。

**解決**: Cloudflare Workers の `c.executionCtx.waitUntil()` を使い、**レスポンスを返した後もバックグラウンドで処理を継続**させる。
→ 画面遷移は 数百ms〜1秒 に短縮、通知は数秒後に届く。

---

## 🎯 汎用ヘルパー: runInBackground

任意のルートファイル（例: `src/routes/requests.ts`）に配置。

```typescript
/**
 * バックグラウンド実行ヘルパー
 * Cloudflare Workers の waitUntil() を使い、レスポンス返却後も処理を継続実行させる。
 * これにより SMTP / LINE WORKS API 待ちで画面遷移が遅くなるのを防ぐ。
 * executionCtx 未対応環境（ローカル wrangler dev の一部モード等）ではフォールバックで
 * 単純に Promise を投げて画面遷移を優先する（未await でも処理は継続する）。
 */
function runInBackground(c: any, task: () => Promise<void>): void {
  const p = (async () => {
    try {
      await task()
    } catch (e) {
      console.error('[BG] バックグラウンドタスクエラー:', e)
    }
  })()
  try {
    c.executionCtx.waitUntil(p)
  } catch {
    // ローカル環境等で executionCtx が使えない場合は投げっぱなし（未 await）
  }
}
```

## 📝 使い方

### Before（遅い）
```typescript
requests.post('/:id/approve', async (c) => {
  // ... DB更新 ...

  // ⚠️ 外部API を await
  await sendNotification(db, 'approved', userId, {...})  // 1〜3秒待たされる
  await sendMail(smtp, {...})                              // 1〜2秒待たされる

  return c.redirect('/requests')  // やっと遷移
})
```

### After（速い）
```typescript
requests.post('/:id/approve', async (c) => {
  // ... DB更新 ...

  // ✨ 通知はバックグラウンドで送信
  runInBackground(c, async () => {
    await sendNotification(db, 'approved', userId, {...})
    await sendMail(smtp, {...})
  })

  return c.redirect('/requests')  // 即座に遷移
})
```

## 🎯 適用対象（rental-circulation-appでの実例）

| 処理 | ハンドラ | 通知先 |
|---|---|---|
| 新規申請 | `POST /` | 承認者Step1 |
| 承認（次あり） | `POST /:id/review/:stepId` (approve) | 次の承認者 |
| 承認（最終） | 同上 | 申請者に完了通知 |
| 否決 | 同上 (reject) | 申請者 |
| 保留 | 同上 (hold) | 申請者 |
| 差し戻し | 同上 (return) | 申請者 |
| 保留への回答 | `POST /:id/answer/:stepId` | 依頼元承認者 |
| 再申請 | `POST /:id/resubmit` | 全承認者 or Step1 |
| Google Drive 保存 | Step2 承認時 | -（サイレント処理） |

## ⚠️ 使ってはいけない場所

**「レスポンス内容自体が処理結果に依存する場合」は使えません。**

例:
- ❌ ログイン処理（認証結果を返す必要がある）
- ❌ ファイルダウンロード（本文が必要）
- ❌ CSV出力（内容を返す必要がある）
- ✅ **通知送信**（本体処理と独立している）← ここが理想

## 🔍 動作確認方法

### 開発中に効いているか確認する

Cloudflare Pages ログを開いて（Cloudflare Dashboard → Workers & Pages → プロジェクト → Deployments → Logs）、
以下のログが出ていれば OK：

```
[BG] バックグラウンドタスク完了 (省略可)
```

エラー時：
```
[BG] バックグラウンドタスクエラー: <詳細>
```

### 体感確認

`console.time()` / `console.timeEnd()` で遷移前後を計測：
```typescript
console.time('response')
runInBackground(c, () => sendNotification(...))
const res = c.redirect('/next')
console.timeEnd('response')  // 数十ms〜数百ms
return res
```

## 💡 高度な使い方

### 失敗をDBに記録する

```typescript
runInBackground(c, async () => {
  try {
    await sendNotification(db, 'approved', userId, {...})
    await db.prepare('INSERT INTO notification_logs (...) VALUES (..., "sent")').run()
  } catch (e) {
    await db.prepare('INSERT INTO notification_logs (...) VALUES (..., "failed", ?)').bind(String(e)).run()
    throw e
  }
})
```

### 複数タスクの並列実行

```typescript
runInBackground(c, async () => {
  await Promise.all([
    sendNotification(db, 'approved', user1, {...}),
    sendNotification(db, 'approved', user2, {...}),
    sendNotification(db, 'approved', user3, {...}),
  ])
})
```
