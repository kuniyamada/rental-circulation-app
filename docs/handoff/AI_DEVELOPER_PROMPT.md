# 送金依頼管理システム開発中AI向け 指示プロンプト

**このファイルの使い方**:
以下のプロンプト全体をコピーして、送金依頼管理システムを開発中のAIディベロッパーに投げてください。
AIはこのプロンプトを読んで、必要な資料を確認しながら実装を進めます。

---

## 🤖 コピペ用プロンプト（ここから）

```
【引き継ぎ資料の適用依頼】

あなたは Cloudflare Pages + Hono + TypeScript で「送金依頼管理システム」を開発中のAIディベロッパーです。

姉妹システムの「賃貸物件回覧承認システム (rental-circulation-app)」で開発済みのノウハウ・コードを引き継ぐことになりました。

引き継ぎ資料は以下のディレクトリに配置されています:
- `docs/handoff/` — 各種ノウハウMarkdown資料 (A1〜C4)
- `docs/handoff/code-package/` — そのままコピー可能なコアファイル群

## ステップ1: まず全体像を把握してください

以下のコマンドで、引き継ぎ資料の目次と内容を確認してください:
- `cat docs/handoff/README.md` (全体目次)
- `ls docs/handoff/` (資料一覧)
- `ls docs/handoff/code-package/` (コード一覧)

## ステップ2: 現在のシステム状況を確認してください

送金依頼管理システムの現状を以下で確認:
- `ls src/routes/` (どのルートが実装済みか)
- `ls src/lib/` (どのライブラリが実装済みか)
- `ls migrations/` (どのマイグレーションが適用済みか)
- `cat wrangler.jsonc` (Cloudflare設定)
- `cat package.json` (依存パッケージ)

## ステップ3: 未実装機能を洗い出す

現在の送金依頼システムのメニュー(添付キャプチャ):
- ダッシュボード
- 依頼一覧・検索
- 依頼入力
- パスワード変更
- ユーザー管理
- 物件管理マスタ
- 支払先マスタ
- 科目マスタ
- CSV出力
- 通知・リマインダー設定
- ★★★ Drive自動保存 (メニューだけあって未実装) ★★★
- データバックアップ
- 監査ログ

引き継ぎ元 (rental-circulation-app) には以下のノウハウが揃っています:
- A1: Google Drive 自動保存 (⭐最重要・未実装のメニュー)
- A2: 通知処理のバックグラウンド化 (waitUntil)
- A3: 成功トースト表示
- A4: 共通レイアウト (layout.ts)
- A5: ファビコン設定
- B1: 添付ファイル管理 (R2 + attachments)
- B2: 回覧承認フロー (Step1→2→3)
- B3: 差戻し/否決/保留/再申請
- B4: テストモード
- B5: メール + LINE WORKS 統合通知
- B6: セッション認証
- B7: リマインダー Cron
- B8: データバックアップ
- C1: Excel/CSV 一括インポート
- C2: 申請番号自動採番
- C3: JST 日時処理
- C4: 監査ログ

## ステップ4: 実装計画を作成してください

現状と引き継ぎ資料を突き合わせ、以下を判定して実装計画を提案してください:

1. **既に類似実装がある機能**: そのまま使うか、資料のノウハウで改良するか判断
2. **未実装の機能**: 資料に沿って新規実装（特に「A1 Drive自動保存」は最優先）
3. **送金依頼固有の調整が必要な部分**: ドメイン名の置換 (application → request, マンション → 物件, 申請者 → 依頼者 など)

## ステップ5: 実装は 「A1: Drive自動保存」から着手してください

これはユーザーが特に必要としている機能です。以下の資料に完全な手順があります:
- `docs/handoff/A1_GoogleDrive自動保存.md` (⭐必読)
- `docs/handoff/code-package/src/lib/drive-client.ts` (改変不要でコピー)
- `docs/handoff/code-package/src/lib/drive-sync.ts` (ドメイン置換で流用)
- `docs/handoff/code-package/src/routes/drive.ts` (ドメイン置換で流用)
- `docs/handoff/code-package/migrations/0015_drive_uploads.sql` (そのまま流用可)

追加で必要:
- `docs/handoff/A2_通知バックグラウンド化.md` (runInBackground ヘルパー)

## ステップ6: 実装前にユーザーに確認してください

いきなり実装せず、以下をユーザーに確認:
1. 実装計画（どのノウハウをどの順で入れるか）
2. 各機能のシステム固有パラメータ（例: Drive自動保存のフォルダ命名規則、ファイル名パターン）
3. Google OAuth設定 (Client ID / Secret / refresh_token / Folder ID) は既に取得済みか

## ステップ7: 実装 → デプロイ → ユーザーに動作確認依頼

各機能を実装後、ビルド・デプロイして、ユーザーに動作確認をお願いしてください。

## 重要な原則

1. **既存の送金依頼システムのコード規約に合わせる** — 引き継ぎ資料は「元システムのやり方」なので、必要なら送金依頼側のスタイルにアレンジ
2. **ドメイン名は送金依頼向けに置換** — 「マンション」「申請」「請求書回覧」等を送金依頼固有の用語に
3. **既存機能を壊さない** — 現在動いている部分は触らない
4. **A1 (Drive自動保存) を最優先** — ユーザーが特に期待している機能
5. **ユーザー承認を得てから実装** — 大きな変更は必ず事前確認
```
