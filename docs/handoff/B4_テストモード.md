# B4: テストモード (本番影響なくテスト可能)

**用途**: 本番運用中のシステムで、ユーザーごとに「テストモードON」にしてテスト依頼を作成可能にする仕組み。

**特徴**:
- ユーザーごとにON/OFF切り替え
- テストモードONで作成した依頼は自動的に `is_test=1` フラグ付き
- メール件名・LINE WORKSメッセージに `[TEST]` プレフィックス
- 実業務データと混ざらないよう視覚的に区別

---

## 📁 DB追加カラム

### users テーブル
```sql
ALTER TABLE users ADD COLUMN test_mode INTEGER NOT NULL DEFAULT 0;
```

### applications テーブル (送金依頼版では requests)
```sql
ALTER TABLE applications ADD COLUMN is_test INTEGER NOT NULL DEFAULT 0;
```

---

## 🎯 依頼作成時のフラグ設定

```typescript
requests.post('/', async (c) => {
  const user = await getSessionUser(...)
  // ユーザーのテストモード状態を継承
  const isTestFlag = user.test_mode ? 1 : 0

  await db.prepare('INSERT INTO applications (..., is_test) VALUES (..., ?)').bind(..., isTestFlag).run()
})
```

```html
  <button type="submit" class="bg-[#396999] text-white px-4 py-2 rounded-lg">保存</button>

```

```typescript
admin.post('/test-mode/toggle', async (c) => {
  const body = await c.req.parseBody() as any
  const enabled = body.enabled ? 1 : 0
  await db.prepare('UPDATE users SET test_mode = ? WHERE id = ?').bind(enabled, user.uid).run()
  return c.redirect('/admin/test-mode')
})
```

## 💡 応用: テストデータ一括削除

管理画面に「テストデータ全削除」ボタンを追加。
`WHERE is_test = 1` で全削除可能。

```sql
DELETE FROM attachments WHERE application_id IN (SELECT id FROM applications WHERE is_test = 1);
DELETE FROM circulation_steps WHERE application_id IN (SELECT id FROM applications WHERE is_test = 1);
DELETE FROM notification_logs WHERE application_id IN (SELECT id FROM applications WHERE is_test = 1);
DELETE FROM applications WHERE is_test = 1;
```

削除前に自動バックアップを取ると安心（B8参照）。
